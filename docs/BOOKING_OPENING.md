# เวลาเปิดจองและคืนบริการ

เจ้าของตั้งค่าที่ `/admin/hours` → **แก้ไขค่าเริ่มต้น**: เลือก **เปิดจองล่วงหน้า N วัน เวลา HH:mm** ตาม timezone ของร้าน (`N` ตั้งแต่ 0 ถึง 365) แล้วบันทึก

- คืนบริการ `D` เปิดจองวันที่ `D − N` เวลา `HH:mm`. ลูกค้าเลือกได้ตั้งแต่วันนี้ตามเวลาร้านถึงอีก `N` วัน. `N=0` เปิดรับเฉพาะคืนนี้ตามเวลาเปิดที่ตั้งไว้
- ก่อนแก้ ระบบใช้ `venue_settings.release_days_before` (ค่าเริ่มต้นเดิม 365) คำนวณเวลาเปิด และ `booking_rules.max_advance_days` (ค่าเริ่มต้นเดิม 30) จำกัดวันที่รับคำขอ จึงอาจแสดงว่าเปิดแล้วแต่จองไม่ได้ การบันทึกเวลามาตรฐานเขียนทั้งสองค่าใน transaction เดียวและเก็บ rule version เดิมไว้
- Migration ไม่เปลี่ยนค่าที่ร้านเคยบันทึก. ถ้าค่าเดิมต่างกัน หน้า `/admin/hours` แสดงทั้งเวลาเปิดและจำนวนวันที่ลูกค้าเลือกได้ เจ้าของบันทึกค่าเดียวกันเมื่อพร้อม

**วันพิเศษ:** ตั้งคืนบริการและวัน/เวลาเปิดเฉพาะใน `/admin/hours`. `booking_releases.opens_at` ใช้แทนเวลามาตรฐานของคืนนั้นและเก็บเป็นเวลาจริง ค่าเวลาเดิมที่บันทึกแล้วคงเดิมแม้ร้านเปลี่ยน timezone. วันปิดร้านและช่วงจองล่วงหน้ายังมีผล ถ้าต้องการเปิดคืนพิเศษเร็วกว่าขอบเขตปัจจุบัน ให้เพิ่มจำนวนวันล่วงหน้าก่อน

หน้าเลือกคืนเลือกคืนแรกที่เปิดรับเป็นค่าเริ่มต้น แสดงเฉพาะคืนที่เปิดแล้วในรายการเลือก และแสดงเวลาเปิดของคืนที่ยังไม่เปิดแยกไว้. ลิงก์จากประกาศเปิดหน้าเลือกคืนพร้อมวันที่พิเศษ เมื่อนับถอยหลังครบ เมื่อถึงเที่ยงคืนที่ร้าน หรือเมื่อกลับมาที่แท็บ ระบบอ่านตารางเวลาใหม่

| กรณี | ผลจาก API |
| --- | --- |
| วันที่ก่อนวันนี้ตามเวลาร้านหรือเกินช่วง `N` วัน | `422 DATE_OUT_OF_RANGE` |
| คืนยังไม่ถึงเวลาเปิดปกติหรือเวลาเปิดเฉพาะ | `409 NIGHT_NOT_OPEN` |
| ร้านปิดตามตารางหรือวันปิดพิเศษ | `409 CLOSED` |
| เกินเวลาปิดรับที่ตั้งเฉพาะคืน | `409 BOOKING_CLOSED` |
| อยู่ในช่วงของร้าน แต่โซนหรือโต๊ะมีเพดานสั้นกว่า | `409 TOO_FAR_AHEAD` |

การตัดสินคำขอตรวจช่วงวันและเวลาอีกครั้งก่อนจัดโต๊ะ หากร้านเปลี่ยนตารางระหว่างที่คำขอรอในคิว เจ้าของดูผลปฏิเสธและเวลาตัดสินได้ที่ `/admin/audit`.
