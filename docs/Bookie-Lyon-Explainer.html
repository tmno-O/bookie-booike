7Tech Stack ที่เสนอ

เลือกบริการดูแลโครงสร้างหลักให้ ทีมเน้นกฎจองและความถูกต้อง เหมาะกับเวลา Hackathon

LINE LIFF + Messaging API

LIFF เป็นหน้าจองใน LINE ส่วน Messaging API ส่งบัตรยืนยันจาก OA ร้าน ลูกค้าไม่ต้องติดตั้งแอปเพิ่ม

Backend ตรวจ token และผูก user ID กับ provider/channel ของร้านให้ตรง ก่อนเปิดส่งข้อความ

Next.js API + TypeScript + Zod

สร้าง API ร้าน โซน โต๊ะ และการจอง ใช้ TypeScript ลดชนิดข้อมูลผิด Zod ตรวจข้อมูลที่รับจริงก่อนทำงาน

API รับคำขอและตอบรหัสติดตามเร็ว งานคิวประมวลผลด้วย Worker แยก

Supabase PostgreSQL + Storage

PostgreSQL เก็บข้อมูลหลัก ใช้ transaction และ constraint กันโต๊ะซ้ำ Storage เก็บโลโก้และรูปผังร้าน

DB เป็นหลักฐานสุดท้ายของการครองโต๊ะ ไม่เชื่อสถานะว่างจากหน้าจอเพียงอย่างเดียว

Amazon SQS FIFO + Node.js Worker

SQS พักคำขอช่วงคนกดพร้อมกัน Worker ทำตามลำดับภายในร้าน/คืน ช่วยควบคุมงานที่เข้า DB

Worker รันเป็นบริการแยก ไม่ใช้ request ของ Next.js เป็น consumer ที่รอคิวตลอดเวลา

DB idempotency + notification outbox

จำผลคำขอเดิม กดซ้ำหรือ retry ไม่สร้างจองใหม่ บันทึกงานแจ้งเตือนพร้อม booking แล้วส่ง LINE ภายหลัง

ส่ง LINE ไม่สำเร็จยังดู booking ใน LIFF ได้ การส่งข้อความไม่ขวางคิวกันโต๊ะ

CloudWatch / logs + k6

ติดตาม queue age, backlog, latency และ error ใช้ k6 จำลองคนกดพร้อมกันก่อนเปิดจองจริง

เลือกขนาด API/Worker/DB จากผลทดสอบ ยังไม่อ้างจำนวนคนรองรับหรือรับประกันไม่ล่ม

8Backend: งานที่รับผิดชอบและระบบคิว

รับผิดชอบข้อมูล กฎธุรกิจ API คิวจอง และความถูกต้องของผลลัพธ์

1. ร้านและสิทธิ์

แยก owner / staff / customer ตรวจสิทธิ์ตามร้าน ตั้งค่าโซน โต๊ะ กฎเวลา วันเปิดรับ และ connection ของ OA ร้าน

2. การจองและสถานะ

API ดูโต๊ะว่าง สร้างคำขอ ดูผล ดูการจอง และยกเลิก Staff ใช้กฎ inventory และคิวเดียวกับลูกค้า เก็บผู้ทำรายการ

เมื่อถึงเวลาเปิดจอง

เตรียมรายการใน LIFFเลือกไว้ล่วงหน้า ยังไม่กันโต๊ะและยังไม่ได้ลำดับคิว ใช้เวลา server ตัดสินว่าเปิดรับแล้วหรือยัง
กดยืนยัน API รับเข้าคิวตรวจตัวตน เวลา และข้อมูล ใช้ Idempotency-Key เดิมเมื่อ retry เมื่อ SQS รับสำเร็จจึงตอบ 202 พร้อมรหัสติดตาม ยังไม่ได้โต๊ะ
Worker กันโต๊ะใน PostgreSQLMessageGroupId แยกตามร้าน/คืน ประมวลผลกลุ่มเดียวตามลำดับ ใช้ transaction ตรวจและกันโต๊ะสำเร็จ บันทึกผลก่อนลบข้อความจากคิว
ลูกค้าดูผลและรับข้อความโต๊ะว่างจึงยืนยัน หากเต็มแจ้งผลตามจริง ใช้ outbox ส่งจาก OA ร้าน ตรวจ provider/user mapping และ retry แยกจากงานจอง
เกณฑ์ความยุติธรรมและการกู้ระบบลำดับนับเมื่อ SQS รับคำขอสำเร็จ ไม่ใช่เวลานิ้วกดหรือเวลามือถือ Worker ต้องมี visibility timeout/lease และ DB idempotency พร้อมกู้ช่องว่างระหว่าง broker กับ DB ไม่พึ่ง SQS dedup เพียงอย่างเดียว
SQS เหมาะกับ Hackathon ไหม?เหมาะเมื่อคิวเปิดจองเป็นแกน ฟรี 1 ล้าน requests/เดือนตามเงื่อนไข รวม send/receive/delete และ polling ไม่ใช่ 1 ล้าน booking ราคา Singapore FIFO หลังส่วนฟรี USD 0.50 ต่อ 1 ล้าน requests ที่คิดเงิน ไม่รวม Worker/logs/transfer/ภาษี
